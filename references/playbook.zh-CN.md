# 产品同时给人用、给 AI 用：通用规则

> 中文版。英文版 [playbook.md](playbook.md) 为准。

> 来源：2026-10-28 给 Shuttlely.ca 做的一套「人能下单、AI 也能下单」。
> 适用：任何卖服务或商品的产品（包车、房产税申诉、排版、施工报价……）。
> 用法：第 1 部分是原则，第 2 部分是逐条清单，第 3 部分可以原样贴进项目的 `AGENTS.md` / `CLAUDE.md`。

---

## 1. 五条原则

1. **一个产品，两个入口。** 人走网页，负责体验和最终决定；AI 走接口，负责查询和办事。两边共用同一份价格、同一套规则、同一条下单流程。**绝不能各算各的价。**
2. **先只读，再动手。** 先开放「查」（目录、报价），这一步没有风险。「办」（下单、发询价）要等用户本人同意才做。
3. **AI 下的单不收钱。** AI 提交的订单只生成订单号；由人确认档期或可行性后，再发付款或定金链接。AI 下错单的代价是零，这是整套做法安全的根本。
4. **选择题优先。** 人看的表单尽量做成按钮、选项、日期选择器、加减号；只有选了「定制」才给文字框。AI 用的接口也一样：用固定的取值（城市代号、线路代号、枚举值），不要自由文本。人好填，机器也好填。
5. **不押注单一平台。** 用公开、通用的格式（OpenAPI + MCP + llms.txt），不为某一家 AI 平台定制。等真有平台带来订单，再接它的专门协议。

## 2. 逐条清单（按顺序做）

### 第 1 步：只读接口（半天）
- [ ] `GET /api/agent/catalog`：列出所有能卖的东西（服务、线路、地区），每项包括：代号、名称、能否即时报价、起步价、详情页网址。
- [ ] `POST /api/agent/quote`：输入结构化需求，返回价格区间、定金、「为什么需要人工报价」的理由，以及一个人能打开核对的网址。
- [ ] **报价必须调用网站本身的计价函数**（同一个解析器、同一份价格表），不许另写一份。写一条测试：接口报价 = 网页报价。
- [ ] 不能即时报价的情况，要返回明确的错误代码，并告诉 AI 下一步调哪个接口（例如 `written_quote_only → request_quote`）。
- [ ] 只读接口开放跨域访问（`Access-Control-Allow-Origin: *`），可以缓存几分钟。

### 第 2 步：下单 / 询价接口（半天到一天）
- [ ] `POST /api/agent/orders`，必填：
  - `requestId`（UUID）：同一个 id 重发，只返回第一次的结果，**永远不会生成第二张单**。
  - `travellerConsent: true`（或 `customerConsent`）：没有就拒绝，并在错误里写清楚要先征得用户同意、附上条款网址。
  - 用户的姓名和邮箱：确认邮件发给用户本人，让真人看到。
- [ ] 下单走网站同一条流程（同一个组装订单的函数、同一封邮件）。**服务器自己重新算价，不信 AI 传来的任何价格。**
- [ ] 在订单备注里自动标上「通过 Agent 接口下单 by XXX」，让运营一眼看出来源。
- [ ] 频率限制：每个 IP 15 分钟内几单、每个收件邮箱每天几单，再加一个全站上限。超出返回 429 和 `Retry-After`。**内存计数只是兜底**，多实例的平台流量一大，要换成共享存储或平台防火墙限流。
- [ ] **不能变成替别人发信的工具**：会发到订单邮箱的确认信里，客户填写的内容（姓名等）不许带网址、域名、邮箱或标记；网页表单也套同一个检查。
- [ ] **写接口只给服务器调用**：请求带了别的网站的 `Origin` 就返回 403，也不发跨域头（MCP 规范本身也要求校验 Origin）。只读接口才开放跨域。
- [ ] 同一个 requestId 配不同内容，返回 409，不要悄悄返回第一次的结果。
- [ ] 网页上的法律或业务红线（不能承诺的、不能给的意见），AI 接口同样要守。
- [ ] 返回订单号、当前状态，以及一句「接下来会发生什么」（例如「2 小时内邮件确认，之后才收定金，现在没有扣款」）。
- [ ] 不能即时成交的（其他城市、定制需求）走 `POST /api/agent/inquiries`，规则同上，发到同一个询价收件箱。

### 第 3 步：MCP 接入点（半天）
- [ ] `POST /api/mcp`：Streamable HTTP、无状态，每次请求返回一个 JSON。不需要登录，也不需要服务器推送（GET 返回 405）。
- [ ] 支持 `initialize`（按对方要的版本回，支持 2025-06-18 / 2025-03-26 / 2024-11-05）、`ping`、`tools/list`、`tools/call`；通知类消息（没有 id 的）返回 202。
- [ ] 工具和第 1、2 步一一对应，例如：`list_*` / `get_quote` / `place_order` / `request_quote`。
- [ ] 查工具名用 `Object.hasOwn`，不用 `in`（否则 `constructor` 这类内置名字也会被当成工具）。先校验 Origin，不发跨域头。
- [ ] 工具标好提示：只读工具 `readOnlyHint: true`；下单工具 `idempotentHint: true`、`destructiveHint: false`。
- [ ] 每个工具的说明里写明：只有在用户同意后才调用，不会扣款。
- [ ] `initialize` 的 `instructions` 用两三句话讲清楚这个产品卖什么、先调哪个工具。
- [ ] 工具出错时用 `isError: true` 返回，并把原因放进 `structuredContent`。不要直接抛 JSON-RPC 错误，这样 AI 才能读到原因、自己改正。

### 第 4 步：公开说明（1 小时）
- [ ] `/openapi.json`：从**同一份 JSON Schema** 生成，和 MCP 工具共用，不会对不上。
- [ ] `/llms.txt`：用几行字写清楚：卖什么、价格怎么算、哪些情况要人工、接口和 MCP 的网址、每个接口一个请求例子、「不收款、需要用户同意」。**内容从价格表代码生成，不要手抄数字。**
- [ ] 网页详情页在服务器端渲染（不靠 JavaScript），让不运行脚本的 AI 也能读到价格和行程。
- [ ] 结构化数据（schema.org）写上服务、价格、地区、营业信息。

### 第 5 步：测试与上线
- [ ] 测试至少覆盖：目录完整；接口报价 = 网页报价；未知代号、过期日期、超出范围都有明确错误；没有同意不能下单；同一个 requestId 不会重复下单，换内容返回 409；频率限制（IP、收件邮箱）生效；带网址的姓名被拒；别的网站的 Origin 返回 403；MCP 握手、列工具、调用、通知，以及内置名字工具被拒。
- [ ] 本地真的调一遍每个接口（下单在本地没有邮件配置时应返回 503「什么都没下单」）。
- [ ] 上线后用真实地址调一次只读接口和 MCP 握手。真实下单只用标了「测试，请忽略」的单，事后在收件箱确认。

## 3. 可直接贴进项目的规则（AGENTS.md / CLAUDE.md）

```markdown
## 给 AI Agent 用的规则（Agent-ready）
- 人和 AI 共用一套价格、规则、下单流程；接口报价必须调用网页同一个计价函数，并有测试保证两者一致。
- 只读接口（目录、报价）随便开放；下单和询价接口必须要求 requestId（防重复）+ 用户同意标志 + 用户邮箱。
- AI 下单永远不收款：只生成订单号，人工确认后再发付款链接。服务器自己重新算价，不信请求里的价格。
- 订单备注自动标「via agent API by <agentName>」；按 IP、收件邮箱、全站做频率限制，超出返回 429（内存计数只是兜底，流量大了换共享存储）。
- 会发给订单邮箱的信里，客户填写的姓名等内容不许带网址、域名、邮箱；网页表单和接口共用同一个检查。
- 下单、询价、MCP 只给服务器调用：带别的网站 Origin 的请求返回 403，不发跨域头；只读接口才开放跨域。
- 同一个 requestId 配不同内容返回 409；MCP 查工具名用 Object.hasOwn。
- 网页上的法律或业务红线，AI 接口同样要守。
- 表单和接口都优先用选项或枚举，只有「定制」才用自由文本。
- MCP 端点 /api/mcp（无状态 Streamable HTTP），工具与 REST 接口一一对应，共用 lib 里同一份 JSON Schema，OpenAPI 也从它生成。
- llms.txt 写清楚接口地址、请求例子、「不收款、需同意」，数字从价格表代码生成。
- 改价格、规则或下单字段时，同步检查：网页、REST 接口、MCP 工具、OpenAPI、llms.txt 五处是否一致（靠共用代码和测试保证，而不是手改五处）。
```

## 4. 各产品怎么套（举例，要按项目核实）

| 产品 | 目录（catalog） | 即时报价 | 需要人工的 | AI 下单后 |
|---|---|---|---|---|
| Shuttlely 包车 | 城市 × 线路 | 多伦多线路按价格表 | 其他城市、8 人以上、节假日 | 订单号 → 人工确认档期 → 发定金链接 |
| 房产税申诉工具 | 支持的地区 | 「省税估算」+ 固定服务费（⚠ 估价师法不允许给价值意见的地方，接口也不能给） | 不支持的地区 | 订单号 → 用户本人通过邮件里的链接付款 |
| 论文排版工具 | 格式（APA/MLA/Chicago） | 免费 / 付费档价格 | 特殊格式 | 返回处理结果或付款链接 |
| 施工报价 | 施工项目类型 | 按单价表估算 | 现场勘察项 | 生成询价单 → 人工回复正式报价 |

只有第一行是做好的，其余几行是举例，不是成品设计。第 0 步要先读真实代码、跟用户确认，不要照着这张表直接做。

共同点：**AI 能查、能提交，但「钱」和「最终确认」永远留在人手里。**
